# 積水アプリ登録チーム（サイト操作の実行部隊）

## 役割
`C:\kowa-automation\sekisui_app\登録キュー\` の登録指示書JSONを、工事店コミュニティサイト（https://shmlc.my.site.com/Construction/s/）に登録する。**保存まで**が標準。送信は別途社長GO。

## 必読資料
- 操作仕様書：`C:\kowa-automation\sekisui_app\操作仕様書_見積登録_2026-07-24.md`（マニュアル37頁+実機調査の統合版）
- 項目マスタ：`C:\kowa-automation\sekisui_app\項目マスタ_2026-07-24.txt`

## ログイン
社長のChrome（claude-in-chrome）のセッションでそのまま入れる。ログイン画面が出たら社長に一声（SHALDS: shmlc.lightning.force.com → 「工事店コミュニティへのリンク」）。パスワードは扱わない。

## 登録手順（実証済みの型）
1. **案件作成**：/Construction/s/searchproperty → 物件コード欄に物件№ → 検索 → この物件を選択 →（棟1つならスキップ）→ 号室選択。**号室マスタが空の物件は「号室を選択しない」**で進み、見積名に「◯◯号室」を明記 → 確認画面 → 案件を作成する
2. **見積作成**：案件詳細「見積作成」→ 見積名（末尾クリック→End→追記が確実）→ 作成 → 「見積に遷移」（新タブが開く）
3. **明細・マスタ行**：グループ--なし--のまま「項目マスタ表示」→ 約10秒待つ → **JSでlightning-inputに .checked=true + CustomEvent('change') を発火**して対象コードを一括チェック（shadowRoot再帰走査で行特定・**可視trのみ対象**=同一行が10重複製されているため）→「追加する」→ 単価・単位・備考コードが自動で入る
   - **行順（社長指示 2026-07-24）＝内装職人系→クリーニング職人系→社内系**。マスタ追加を**3回に分けて**実行する：1回目=内装系コード（604/605/602/606）だけチェック→追加、2回目=クリーニング系（601）→追加、3回目=残り（600/603/607/609〜617）→追加。追加順がそのまま行順になる
4. **単価・原価・数量入力（社長確定ルール 2026-07-24）**：**triple_click（全選択）＋実type＋バッチ末尾Tab**（合成イベントのvalue設定はclassifierに弾かれる。⚠️ctrl+aは「a」が文字として入り数値欄がエラーになる事故あり→triple_click一択）
   - **見積単価（上段）＝積水の売上**（チェックシート退去者/オーナー列）。マスタ追加直後は光和受注額が入っているので売上額に書き換える
   - **見積原価単価（下段）＝弊社の受注額**（チェックシート不動産列）。ここは使う（マニュアルの「グレー非使用」は光和運用では原価単価・予定数量に限り例外）
   - 数量は上段（見積数量）へ。下段の予定数量は上段から自動コピーされる（無害）
   - **座標運用**：明細行のlightning-inputはtr.toprow内に10個（i0項目名/i1規格/i2見積単価/i3原価単価/i4見積数量/i6見積金額/i8備考）。**バッチごとにshadowRoot走査JSで座標再取得**（スクショ座標=JS座標×1568/innerWidth。エラー表示で行高が変わり座標が全ズレするため流用禁止）。2〜4行入力→スクショ検証→次バッチ
   - 集計欄で検算：見積金額合計=売上計・予算原価合計=受注計・粗利率が妥当か確認
4-2. **規格欄（項目名の下段・MGO__Standard__c）**：チェックシート仕様/品番の文言（巾木下面/E5101/物置内清掃/単三等）を入れる（社長指示2026-07-24）。**入力は focus()+type方式が確実**：JSで対象行の `lis[1].focus()` →実type→Tab。座標クリック不要でズレに強い（下原201で4件実証済み）。この方式は単価・数量にも使える（focusはclassifierに弾かれない）
5. **手入力行**：「＋」で行追加 → 項目名／単価／原価／数量をクリック+type → 単位はドロップダウンクリック→**スクショでリスト座標確認**→選択肢クリック（「式」はリスト2番目・下部の行はリストが上向きに開く）
   - ⚠️**項目名のつもりで「行コマンド検索」欄に日本語を入れると勝手にグループ（タブ）が作られる事故**あり（実例「諸経費」）。空グループは行が無ければ保存で消える（実証済）ので慌てない
6. **検算**：見積金額合計が指示書の期待合計と一致することを確認。不一致なら保存せず⚠️報告
7. **保存**：「保存」→ F5リロードして明細が残っていることを確認（＝保存成功の証拠）
   - ⚠️**保存で手入力行の単価・数量が消え金額だけ残ることがある**（実例：諸経費行）。リロード後にJSで全行のt/g/q/amtを検証し、消えていたら入れ直して再保存
8. **報告**：案件登録番号・見積番号・合計・スクショで部長へ

## ⚠️ 守る（厳守）
- **「不動産に見積送信」チェック（積水への送信）は社長の明示指示があるときだけ。** 標準は保存＝未送信まで
- 明細下段のグレー欄のうち項目マスタ/規格/費用種別/社内メモと緑鉛筆は**入力禁止**（マニュアル明記）。ただし**見積原価単価は光和運用で使用する**（弊社受注額を入れる・社長確定2026-07-24）
- 期待合計と不一致のまま保存しない。誤登録した行は「×」で削除してから保存
- 見積破棄・案件削除などの取消操作は社長確認後
