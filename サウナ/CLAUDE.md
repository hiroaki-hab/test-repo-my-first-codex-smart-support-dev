## 1. 絶対に守る原則（破ると事故になる）

| # | 原則 | 理由 |
|---|---|---|
| 1 | **Googleカレンダー「サウナ予約」が唯一の真実源** | 迷ったら必ずカレンダーを基準に判断する |
| 2 | **人間が手書きした行・予定は絶対に上書き・削除しない** | 人間の入力が常に優先。自動同期で触らない |
| 3 | **SB / CHILLNN のパスワードをAIが入力しない** | ログインは必ず人間に依頼。botは手動再ログインへ誘導 |
| 4 | **16:00–18:00 は毎日「清掃時間」で必ず売止** | この枠を予約で取られると清掃ができず事故になる |
| 5 | **Salon Board は「1アカウント＝1セッション」** | botと人間のChromeが同時ログインするとセッションが壊れる |
| 6 | **HPBで「100pt利用＋現地払い」予約は会計時 ¥-100 調整** | 調整を忘れると売上がズレる。カレンダーに⚠️必須 |
| 7 | **CHILLNN受付期間外（受付終了済み枠）を販売中に戻さない** | CHILLNNが操作を拒否する。エラーの元 |
| 8 | **停止中のCoworkスケジュールタスク3つを絶対に再有効化しない** | dedupe未修正でGmail下書きスパムが再発する（→`ナレッジ/監視体制.md`） |
| 9 | **普段使いのChromeでSalon Boardのタブを開きっぱなしにしない** | botと同時ログインでセッションが壊れる（原則5の具体版） |
| 10 | **佐藤様の個人カレンダー(primary)も毎回読む** | ゴルフ・飲み会・誕生日を営業の売止に連動させるため |

## 3. カレンダー記法（イベントの命名規約）

「サウナ予約」カレンダーでは、**イベント名の冒頭プレフィックスと色**で由来を分類します。

| プレフィックス例 | 色（colorId） | 意味 |
|---|---|---|
| `[KÖWA] ◯◯さん (2名)` | Basil(10) | CHILLNN由来 |
| `[SB] ◯◯さん (n名)` | Tangerine(6) | Salon Board由来 |
| `[トリドリ] ◯◯ (n名)` | Grape(3) | トリドリ案件 |
| `[電話] ◯◯さん (n名)` | — | 電話・直接予約 |
| `[KÖWA/キャンセル] ◯◯さん` | Graphite(8)グレー | キャンセル済 |
| `[KÖWA/売り止め] 夜営業休（◯◯のため）` | — | オーナー所用ブロック |
| （プレフィックス無し） | — | 人間の手動入力（取材等）→**触らない** |

## 4. プラン × 日付のマッチングルール

営業日に応じて販売するプランを切り替え、合わないプランは売止します。

| 状況 | 対応 |
|---|---|
| **平日（月–金、祝日除く）** | 平日プラン販売／休日プランは全売止 |
| **土日祝** | 休日プラン販売／平日プランは全売止 |
| **日曜の終日予定（ゴルフ等）** | 13–16 と 18–21 の**両方**売止 |
| **平日・土曜の終日予定** | **18–21 のみ**売止（事務員対応で日中営業可）※佐藤様明言済 |
| **18時以降開始の予定（飲み会等）** | 18–21 売止 |

> ✅ 「日曜デフォルトは営業（予定があれば閉店）」は**社長確認済み(2026-06-03)**。日曜も通常営業し、終日予定がある日だけ売止＝現行botロジックで正しい。

## 5. 仕事の進め方・トーン（佐藤様の好み）

- 🔔 **重要事項は冒頭に🔔マーク**を付けて視覚的に目立たせる
- **AskUserQuestion を積極的に使う**（佐藤様は他業務と並行 → 通知で気づける）
- 佐藤様は**スピード重視・即対応**を期待。「明日やります」等の先送り提案はしない
- 困ったら **カレンダー（真実源）を基準**に考える
- ✅ **文体トーン＝親しみ・フレンドリー（絵文字OK）**（社長確認 2026-06-03）。堅すぎず距離が近い接客文。SNSも同トーン

## 6. 既知の落とし穴（同じ失敗を繰り返さない）

- **大量のGmail下書きが生成された** → 件名のブレでdedupe失敗のサイン。**即停止**して原因を見る
- **SBログインURL** は `/login/`（`/KLP/login/login/` は誤り）
- **Playwright Chromiumが見えない** → 多くはバックグラウンド起動。画面中央に位置指定する
- **state.json方式のログイン保持が安定**。permanent profile方式は脆い（実証済み）
- **CHILLNN受付期間内（今日＋1日）の枠は触らない**（受付終了済みのため）

## 7. セキュリティ（厳守）

- `credentials.json` / `token.json` / `state.json`（Cookie・認証情報）は **絶対にリポジトリにコミットしない**
- これらはローカルPC（`C:\KowaBot\`）にのみ存在させる
- Apps Script Webhook URL は**実質的な秘密エンドポイント**。公開リポジトリには置かない
