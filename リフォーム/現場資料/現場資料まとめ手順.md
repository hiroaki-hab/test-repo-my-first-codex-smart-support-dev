# 現場資料のまとめ方（スマホ投げ込み → 業者向け資料）

> 社長がスマホ(claude.aiアプリ)から**現調写真・議事録・音声メモを投げるだけ**で、
> AIが**業者さんが現場でそのまま見られる1枚資料(PDF)**に整えて保存する仕組み。

---

## 全体の流れ

```
スマホから投げ込み（写真／議事録／音声メモ＝文字起こし）
   │  「明石台の現調写真」「◯◯様邸の打合せメモ」など物件名を一言添える
   ▼
AI が仕分け・整理
   │  ① 物件フォルダへ保存（写真はリネーム）
   │  ② 要点を抽出（決定事項・寸法・品番・注意点・宿題）
   ▼
現場資料PDF を更新（v1 → v2 → …）
   │  業者向けレイアウト（下記「資料の型」）
   ▼
社長へPDFを返す → OKなら業者へ共有（LINE/印刷）
```

## フォルダ構成

```
リフォーム/現場資料/
├── 現場資料まとめ手順.md   ← この文書
└── <物件名>/               例: 明石台石井様邸/
    ├── 現場資料_<物件名>_vN.pdf   ← 業者に渡す完成品（最新版が正）
    ├── 現場資料_<物件名>_vN.html  ← PDFの元（編集・再生成用）
    ├── 写真/
    │   └── YYYYMMDD_連番_内容.jpg  例: 20260716_01_階段クロス浮き.jpg
    └── メモ/
        └── YYYYMMDD_議事録or音声メモ_要点.md
```

## 資料の型（業者向けPDF・A4縦・この順で）

1. **物件ヘッダー** — 物件名／住所／工期／担当業者／連絡窓口。⚠️未確定は赤で明示
2. **工程表** — 日程の帯（仮工程表と同じ体裁のミニ版）
3. **作業内容** — 工種・範囲・品番・仕様（例: サンゲツSP2503、階段部含む）
4. **現場情報** — 駐車場所／鍵・入室／搬入経路／在宅状況／養生・注意点
5. **写真台帳** — 現調写真＋ひと言キャプション（場所と指示。例:「2F階段 下地補修要」）
6. **決定事項・申送り** — 議事録・音声メモからの要点（箇条書き・日付つき）
7. **⚠️要確認** — 未確定事項（勝手に埋めない。推測は⚠️付き）

## AI側の作業ルール

- 投げ込みに物件名が無ければ**推測せず確認**する（既存物件との紐付け間違い防止）
- 写真は内容がわかる名前にリネームして `写真/` へ保存。**PDFには全点、キャプション付きで載せる**
- 音声メモ・議事録は原文を `メモ/` に残し、PDFには**要点だけ**（業者が読むのは要点）
- 文字は大きめ・専門用語はそのまま・あいまい表現は使わない（現場で迷わせない）
- 更新のたびに版数を上げ（v1→v2）、**ヘッダーに更新日と版数**を明記。古い版は残す
- PDF生成: HTMLを作って `chromium --headless --print-to-pdf`（日本語フォント=IPAゴシック）
- 工期が変わったら仮工程JSONも直して `push_kari_koutei.py` でシートZへ再送信（着地は「仮工程_受信」タブのみ）

## 禁止・注意（工程チーム共通ルール準拠）

- メイン台帳（手書きの板）には自動で書かない
- 個人情報（施主の電話番号等）は社長の指示があるときだけ記載
- 不明点は空欄＋⚠️（推測で確定しない）
