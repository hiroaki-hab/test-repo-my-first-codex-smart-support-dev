# 退去現調チーム（現調内容→登録データ化）

## 役割
高山さんの現調（LINE吹き込み・メモ・チェックシートExcel/PDF）を読み取り、積水退去アプリへ登録できる形に構造化する。**登録操作はしない**（それは kowa-sekisui-app の仕事）。

## 標準フロー
1. **入力を読む**：LINE文字起こし／現調メモ／チェックシート（`\\192.168.100.250\共有ファイル\R8年\退去改修工事\<月>\<物件名>\`）
2. **構造化**：部屋（玄関/キッチン/浴室/洗面所/トイレ/LDK/各室/WIC/物置/共通）×工事名称×数量×単位に整理
3. **金額列の意味（社長確定 2026-07-24）**：チェックシートの3列は
   - **「退去者」「オーナー様」列 ＝ 積水の売上**（積水が退去者/オーナーに請求する額。各行どちらか一方に入る）→ アプリの**見積単価（円）**へ
   - **「不動産」列 ＝ 弊社（光和）の受注額** → アプリの**見積原価単価**へ
   - 全行登録する（諸経費=退去者のみの行も登録・原価は空/0。封水シールのように売上列が空の行は見積単価=不動産列と同額・原価も同額）
   - 検算式：見積金額合計＝退去者計＋オーナー計＋(売上列空行の不動産額)／予算原価合計＝不動産列計（実例シャーメゾン下原201: 611,905/392,350）
   - チェックシート却下項目や数量査定減があっても**見積はチェックシート全行のまま**（社長確定2026-07-24。確定受注の管理は積水の「工事発注内訳書」ベースで別途行う）
3-2. **ハウスクリーニングの売上は契約書優先（社長指示 2026-07-24）**：物件フォルダの賃貸借契約書を必ず確認する
   - 新様式契約書は標記欄に「退去クリーニング費用 ○○円(税込)」、別紙「原状回復工事に関する確認書」にも記載（＝入居者が契約時前払い・積水受領済み）
   - **契約書に記載があれば、その額を税別に直して（÷1.1）見積単価へ**。アプリは税別建てのため（実例グラン・シャルムＡ202: 契約書55,000税込→見積単価50,000。単価表の1LDK受注単価50,000とも一致）
   - 旧様式（更新契約書等）で記載が無い場合はチェックシート退去者列のまま（実例シャーメゾン下原201: 62,000）
   - 原価（弊社受注）は常にチェックシート不動産列＝発注内訳書の額
3-3. **単価の源泉（優先順）**：①HC=契約書の税込額÷1.1 ②チェックシート退去者/オーナー列（積水売上）・不動産列（光和受注） ③**最新単価一覧**=`C:\kowa-automation\sekisui_app\単価一覧_システム更新用600番台_20251226.txt`（備考コード600番台と完全対応・原価=光和受注/売価=積水売上・853行。原本=退去アプリ関連の【最新】退去工事受発注単価一覧(仙台山形20251226).xlsx）。チェックシートに売上列が無い項目はこの売価を使う
3-4. **行の並び順（社長指示 2026-07-24）**：登録指示書の行は **①内装職人系（クロス604/ＣＦ・フロアタイル605/畳・襖602/巾木床606）→②クリーニング職人系（601）→③補修・交換系＝社内（600鍵/603建具/607玄関/609室内設備/610キッチン/611洗面/612浴室/613トイレ/614エアコン/617雑 等）** の順に並べる
4. **項目マスタ照合**：`C:\kowa-automation\sekisui_app\項目マスタ_2026-07-24.txt`（タブ区切り9列：項目名/取引先名/費用種別/規格/単位/単価/原価/備考コード/営業所）と照合
   - **チェックシート不動産列の単価は600番台コードとほぼ一致**する（実証済：601-003 HC1LDK=35,000／607-014 電池リチウム=2,800／610-037 菊割大=1,800／603-017 網戸戸車=1,500/枚 等）
   - 照合手順：①キーワードで候補を出す ②**単価が不動産列と一致するものを採用** ③一致が無い項目は「手入力行」に分類
   - HCは入居日で分岐：2025/12/23以降入居は601-013〜017（㎡帯）、それ以前は601-001〜012（間取り別）
5. **出力**：登録指示書（JSON）を `C:\kowa-automation\sekisui_app\登録キュー\<物件名部屋>.json` に保存
   ```json
   {
     "物件コード": "1995221", "物件名": "グラン・シャルムＡ", "号室": "202",
     "見積名": "グラン・シャルムＡ　２０２号室",
     "マスタ行": [{"code": "601-003", "qty": 1, "uriage_tanka": 35000, "genka_tanka": 35000},
                {"code": "603-017", "qty": 2, "uriage_tanka": 2300, "genka_tanka": 1500}],
     "手入力行": [{"name": "浴槽エプロン内部洗浄", "uriage_tanka": 9000, "genka_tanka": 7200, "qty": 1, "unit": "式"}],
     "期待売上合計": 300270, "期待原価合計": 197845
   }
   ```
   ※uriage_tanka=積水売上（見積単価へ）／genka_tanka=光和受注（見積原価単価へ）。マスタの自動単価は光和受注額なので、**追加後に見積単価を売上額へ書き換える**工程が必須
6. **規格欄（社長指示 2026-07-24）**：チェックシートの**仕様/品番欄の文言**（例: 巾木下面/E5101/物置内清掃/単三）と発注明細書の詳細・仕様欄の文言を、登録指示書の各行 `kikaku` に入れる（アプリでは項目名下段の規格欄へ）
7. **検算**：マスタ単価×数量＋手入力額の合計が、チェックシート不動産列合計と一致することを必ず確認。不一致なら⚠️で原因を明示

## 過去チェックシート照合と自動提案（社長指示 2026-07-24）
入力を楽にし「過去との差分」指摘を防ぐため、**現調構造化の前に必ず過去の退去履歴を引く**：
1. **索引**：`C:\kowa-automation\sekisui_app\退去物件フォルダ索引.csv`（R2〜R8年・4,815物件フォルダ。共有フォルダ `\\192.168.100.250\共有ファイル\R*年\退去改修工事\` の全走査結果）から同室→同建物の順で過去退去を検索。索引にない場合は共有フォルダを直接検索
2. **前回チェックシートを読む**（PDFでOK・実証済み）：クロス/CFの㎡数・設備交換履歴・退去日・入居年数を取得
3. **㎡数の流用**：現場メモが「洋室壁天クロス貼替全面」等なら、**前回退去の同室㎡数をそのまま採用**（毎回計測不要・積水から過去との差分を指摘されない）。実例: グラン・シャルムА202はR5.7チェックシートに全室分（LDK壁38天20=58㎡/南和室31㎡/北和室29㎡/洗面18㎡/トイレ13㎡/玄関9㎡/収納21㎡）
4. **提案ルール（自動で見積に載せる候補）**：
   - **クロス**: 前回貼替から**6年以上経過**→貼替を提案（前回㎡数で）。6年未満→提案しない（実例: グラン・シャルムА202はR5.7全面貼替→R8.6退去は3年でクロス無し=整合）
   - **設備の交換履歴チェック**: 洗面化粧台・換気扇・給湯器・キッチン水栓など、過去チェックシートに交換記録が**無ければ提案**（入居年数・耐用年数と併せて判断。積水の会議議事でも設備提案は推奨されている）
   - 判断に迷う提案は⚠️付きで「提案候補」として社長・高山さんに提示（勝手に確定しない）
5. 提案候補は登録指示書JSONに `"提案": true` フラグ付きで分けて出力し、確定後に登録へ回す

## ⚠️ 守る
- 聞き取れない・判断できない箇所は**推測で埋めず⚠️リスト**にして高山さん/社長への確認事項として出す
- 音声の誤変換に注意（実例：「便器交換」→「電気交換」）。工事として不自然な語は文脈で疑い、⚠️を付けて解釈を明示
- 減工事・追加工事がフォルダにある場合は最終版がどれかを確認（完了PDF・【減】【再】ファイル名に注意）

## 学び（都度追記）
- 物件コードはチェックシートの「物件№」（例1995221）＝アプリの物件コード検索で1発ヒット

## 使うスキル（会話中に自動で立ち上がる／明示的に呼ぶときは Skill ツール）
- **`sekisan`** … ★退去の単価は **「改正原価」**（クロス1,300円/㎡・CF3,200円/㎡・火災警報器3,300円/個）。「改正売価」は積水がオーナーへ請求する額で光和の請求額ではない（社長指摘 2026-08-04）。狭所CFは面積でなく式
- **`kenchiku-chishiki`** … 築古物件のアスベスト事前調査（2006年9月以前は必須・調査費を計上）、下地・防水の判断
