## 1. Salon Board の DOM 操作

### シフト編集 popup の構造
- `#yoteiBlock0` がメインブロック（時間範囲を持つ）
- 「予定を追加する」ボタン `#changeShiftSchedule` は **JS click() で動かない**（既知）
- 回避策：**既存ブロックの時間範囲を拡張**（例 16-18 → 13-21 で複数枠を1ブロックでカバー）
- 複数ブロックがある時は `a.mod_btn_delete_04` で削除可

### 基本設定（/KLP/set/salonSetup/）の予約時質問・確認事項（2026-08-26）
- HPB予約画面の「サロンからお客様への質問」= `textarea#storeAskCustomerQuestion`（全角200字・表示フラグ`storeQuestionDispFlg`）
- 「ご迷惑に関しての注意事項」= `textarea#storeConfirmation`（全角200字。予約画面の確認事項）
- 保存は `#complete`（設定する）1回→「基本設定の設定が完了しました。」表示で成功。失敗時は同URLに赤バナー
- 🔴 **「¥」は使用不可文字**（赤バナー「不正な文字を含んでいます」で保存拒否）→ 金額は「1,500円」表記にする
- 2026-08-26 北様の件: 確認事項の「水着着用必須（無料貸出あり）」が有料化(8/17 水着1,500円/ポンチョ1,200円)後も残り
  無料と誤解される事故 → 「有料レンタル1,500円あり」に修正・質問3)も「有料：水着1,500円・ポンチョ1,200円／無料：タオル・サウナハット」に

### 月間 commit 手順（順番厳守）
1. セル `tr[id="{staff_id}_{yyyymm}"].children[day+2]` 内の `A.shiftdate` をクリック

4. `#update2_{staff_id}_{yyyymm}` をクリック（月末確定）

### スタッフID
- `W001418166` = 平日 予約用（旧：佐藤美慧）
- `W001425317` = 休日 予約用（2026/05/28頃に追加）

## 2. CHILLNN の在庫操作

### プラン順序（DOM上）
1. 平日 13-16 / 2. 平日 18-21 / 3. 土日祝 13-16 / 4. 土日祝 18-21

### ボタン索引計算
`btn_idx = plan_idx * days_in_month + (day - 1)`

### 3状態
- `販売中` → クリックで `売止` へトグル
- `売止` → クリックで `販売中` へトグル
- `不可` → 受付期間外。**触らない**

### 保存
右上「保存」ボタンを最後に1度クリック

### 受付期間（auto-lock）
- 前日4日間程度は CHILLNN が自動売止 → 触らない
- 月末方向（受付期間外）は灰色「不可」 → 触らない

## 3. 業務時間判定ルール（reconcile.py）

| 開始 | 終了 | 売止スロット |
|---|---|---|
| 13:00未満 | 16:00以上 | 13-16 |
| 16:00未満 | 18:00以上 | 16-18（buffer） |
| 18:00未満 | 21:00以上 | 18-21 |

### 個人カレンダーの取扱い
- 終日（誕生日除外）→ 平日・土曜は `16-18 + 18-21`、日曜・祝日は `13-16 + 16-18 + 18-21`
- 18時以降開始 → `18-21`
- 13-17時のみ → 営業継続（無視）

### 5分許容ルール
- `16:00-18:05` ≈ `16:00-18:00` として扱う。手動入力の5分超過は許容、書き換えない

## 4. 🔔 セッションとブラウザの罠（最重要）

### SBセッションの闇
- SBは1アカウント1セッション
- 普段のChromeとPlaywright Chromiumで同時ログインすると、**後からログインした方が勝つ**
- 古い方は「一定時間操作されなかったため」エラーで見せかけの切断扱い
- **解決：SBはPlaywrightのみで触る。普段のChromeのSBタブは閉じる**

### Playwright Chromium が見えない
- 起動引数なしだとOSデフォルト位置（モニター不定）
- v3.6で `--window-position=200,100 --window-size=1280,800` を明示
- `test_chromium.py`（派手なピンク画面）で位置確認できる

### Cowork環境の罠
- `Grouping is not supported by tabs in this window` → シークレット等タブグループ非対応窓が前面。通常Chrome窓を1つ開いて解決
- **タブグループ累積**：各スケジュール実行が新規MCPタブグループ生成 → 数日で100+ → Chrome不良。`chrome://flags/#tab-group-sync-service` をDisabled、bookmarkから手動削除。**再有効化は禁忌**
- **dedupeバグ**：件名がブレて検索一致せず毎回新規下書き。修正版は固定文字列 `[KOWA-FIXED] SB session lost - manual relogin needed` でdedupe

## 6. 運用上のクセ・コツ（事例ベース）

### 月跨ぎの落とし穴
- 🔔 **月初にSB「毎月の受付設定」をしないとシフト編集できない**
  - 7月の事例：佐藤様が手動で受付設定するまでbot動作不可だった
  - 2026-08〜 受付設定は【自動延長中】で自動。ただし**予定ブロックが無いセルはbotが書けない(no_block0)**
    → `sb_month_seed.py`（タスク KowaBot-MonthSeed 毎月2日10:00）が翌月全営業日に16:00-18:00「予定あり」を種付け（2026-08-22）
  - 一括入力のコツ: `#changeShiftScheduleBatch`は**Playwright実クリック**必須／日付selectはゼロ埋め('01')／
    **再読込前に「設定」→#update2で確定**しないと消える／再読込直後の初回セル読みは空になりがち(読み直す)

### CHILLNNホテルポリシー(FAQ)の編集はGraphQL直叩き（2026-08-26）
- 管理画面 施設設定>ホテルポリシー(`admin.chillnn.com/{hotelID}/hotelSettings/hotelPolicy`)の**右上「保存」ボタンは押してもAPIが飛ばず保存されない**（実タイピング・React onChange直呼びでも不可。バリデーションエラーも無し＝アプリ側の不具合と推定）
- ✅ 確実な方法: `api.chillnn.com/host/graphql` へ **HotelPolicyUpdate** mutationを直接POST
  1. 管理ページを開きGraphQL通信から`authorization: Bearer …`ヘッダを捕捉（ページ内fetchで再利用）
  2. `query HotelPolicy(hotelID)`で現行の全フィールドを取得（FAQ=`hotelInfo[{title,description}]`）
  3. **完全ミラー**の入力を作り対象文字列だけ差し替え。⚠️アプリのクエリに無い必須4項目
     `isShowPlanIncludedPrice`/`requiredPlanSelectForReservation`/`defaultInitPeopleNum`/`isCalendarStartFromAvailableMonth`
     も現行値で必ず含める（無いとBAD_USER_INPUTで弾かれる＝書き込み前に検証されるので安全）
  4. userErrors無し→管理画面と公開ページ(`www.chillnn.com/ja/{hotelID}`)再読込で検証。公開反映は即時
- 実績: FAQ「手ぶらでも利用できますか？」のサウナキャップを有料欄→無料欄へ移動(2026-08-26)。実装例=セッションscratchpadの`chillnn_gql_update.py`・変更前バックアップ=`hotel_policy_backup.json`

### CHILLNN受付期間
- 前日12時で当日予約締切
- 約21〜30日先まで受付。それ以降は「不可」グレー表示

### SBの異常時パターン（ログの読み分け）
| 表示 | 意味 |
|---|---|
| 「一定時間操作されなかったため」 | セッションタイムアウト |
| 「URLエラー」 | URLが誤り or SB側の仕様変更 |
| ログイン後すぐ切れる | 同時1セッション制限の違反 |

### ⚠️ CHILLNNの「在庫無」状態（盲点）
- 売止/販売中とは**別の状態**。在庫数を0にしたときに出る
- 🔔 **Python botは「在庫無」を読み取らない**（「不可」と同じ扱いになる）
- 事例：6/21(日)に在庫を1件追加し、在庫数1で営業可能にしたケースあり
  → 在庫数で営業可否を制御する運用がある点に注意
